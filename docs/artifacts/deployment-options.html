Why "hosted on Kiro" isn't a real third option

Kiro (like Claude Code, like any AI coding assistant) is a development-time tool: it has no persistent server process, no built-in scheduler, no uptime guarantee, and its session ends when you close it — the exact same limitation this project already flagged for "a sleeping Mac can't provide 24/7 monitoring." Connectivity from Kiro to Snowflake means Kiro is a convenient client for building and testing against Snowflake — the production workload still needs to actually execute inside Snowflake (Option B) or a real cloud runtime, not inside any coding agent's own session. Presenting it as a co-equal third architecture to a board would overstate what it can do.
