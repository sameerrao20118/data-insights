What "verified" means here

Two different, honest claims — don't collapse them into one "it works."

Logic correctness

16 hand-written test cases — below-minimum history, idempotent reruns, multi-currency independence, no future leakage, cooldown suppression, and 7 more — check the detector does exactly what its spec says.

16 / 16 passing

Detection against embedded ground truth

Precision 0.09, recall 0.66–0.83 across two independently-seeded datasets, against a narrow injected label. This is a development diagnostic, not a clean benchmark — the same session that built the detector also built the labels.

Consistent across 2 seeds

Reproduce this yourself

One command, from the repo root:

./run_demo.sh
— runs tests, both detectors, the evaluation harness, and rebuilds the worklist, in order

Where the output actually lives

var/insights/digest_*.md — narrative digest, one per run, human-readable
var/insights/worklist_*.csv — the unified table shown above, opens directly in Excel/Sheets
var/state.sqlite — transaction-detector history, idempotent across reruns
var/state_external_events.sqlite — macro-event-detector history
Before you show this to anyone: this is a synthetic dataset with injected patterns — no real client, transaction, or event on this page is real. The precision/recall figures above are development diagnostics from a contaminated session (the same work that built the detector also built the test labels), not a validated benchmark. No revenue, conversion, or business outcome is proven or claimed anywhere in this system — see docs/objective.md for exactly what this POC does and doesn't establish.
