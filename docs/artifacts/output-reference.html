Technical approach, by stage

One row per pipeline stage: what technique class is used, and the specific method.

StageTechniqueMethod
Input contractSCHEMATyped column contract (config/entities.yaml) — grain, required columns, currency/time semantics enforced before any row reaches detection logic
Transaction detectionSTATISTICALRolling Median Absolute Deviation (MAD) vs. each account's own trailing history — flags a payment > 6 MAD-multiples above baseline, min. 15 prior transactions
External event matchingRULE-BASEDDeterministic join: event.affected_sector/country against client.sector/country, empty field = wildcard match
RankingDETERMINISTICExplicit weighted formula — magnitude component (MAD-multiples or severity/5) × 0.6-0.7 + recency decay (half-life 14-30 days) × 0.3-0.4
Category taggingRULE-BASEDStatic lookup per rule_version, or direction-conditional lookup per (event_type, direction) pair — no model involved
Narrative generationLLMLocal Ollama, qwen2.5:7b, structured JSON-schema-constrained output, validated against the evidence packet before acceptance; deterministic template fallback on failure
Quality samplingLLMLocal Ollama, llama3.1:8b (different model than the narrator) — samples a subset of accepted narratives, scores faithfulness/action-relevance/clarity 1-5
