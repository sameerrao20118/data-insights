Open with the business problem

30 seconds, no terminal yet

say Relationship managers reach out on a calendar, not on a signal — quarterly check-ins, not "this client just got hit by an energy price shock" or "this account just received a payment three times its normal size." Two kinds of signal go unwatched: what's happening inside a client's own accounts, and what's happening around them in the market. This system watches both and turns them into a ranked, evidence-backed worklist.

03

Name where each kind of logic sits

The question every technical reviewer asks first

StageTechniqueWhy not something else
Detection (transaction)STATISTICAL Rolling median absolute deviation vs. trailing baseline — explainable, no training data needed yet
Detection (external event)RULE-BASED Sector/country match — a join, not a model; nothing to overfit
RankingSTATISTICAL Explicit magnitude + recency formula, every component visible — no opaque score, no ML challenger until real conversion labels exist
Narrative (evidence → text)LLM Local Ollama only, validated against the evidence packet before acceptance; template fallback on failure
Quality checkLLM Sampled judge, deliberately a different model than the narrator
Not built yetML Deferred on purpose — no real RM accept/reject outcomes exist yet to train against
say Machine learning is the one thing deliberately not in this pipeline yet — not because it's hard, but because there's no real outcome data to train it against. Everything running today is either arithmetic you can check by hand, or an LLM writing a sentence about facts a validator already confirmed.
04

Two event categories — endogenous and exogenous

This is the part most NBA systems don't do

Endogenous — the client's own data

A client's own transactions, out of pattern for them specifically.

  • Large incoming payment vs. 90-day trailing baseline
  • Detector: large_incoming_payment.py
  • 7 more trigger types labeled in data, not yet detected (cash-flow stress, FX exposure, treasury surplus, ...)

Exogenous — the world around them

Market/political/industry events, matched by sector + country.

  • Rate changes (ECB), tenders (TED), energy shocks (Eurostat), sanctions, regulation (EUR-Lex), geopolitical events (GDELT), disasters (EM-DAT)
  • Detector: external_macro_event.py
  • Each event now carries source_context — whether that real API is structured/real-time, lagged, or needs LLM extraction first
say A sanction on a country can open an export opportunity for a client in that sector — that's a signal no amount of watching the client's own transactions would ever surface. Both categories write into the same worklist, tagged with the same six recommendation categories, so an RM sees one list, not two.

07

Run it — the whole thing, live

One command, or step through it narrating each stage

./run_demo.sh

Or narrate each stage separately:

python -m pytest tests/ -v                    # 16 tests, both detectors
python -m datainsights.cli                     # endogenous: detect -> rank -> narrate -> digest
python -m external_events.demo_scenario        # exogenous: same shape, external events
python -m datainsights.build_worklist          # unify both into one RM worklist
say Re-running this is idempotent — no duplicate detections, and narratives already generated are served from cache. That's not an accident; it's what lets this run on a schedule later without flooding an RM with repeats of the same thing.
